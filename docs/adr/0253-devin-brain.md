# 0253. The Devin brain: agents think with a person's Devin plan through Cognition's Devin CLI

- Status: Accepted (2026-11-23; built: runner, engine, server, the shared client, the web, the phone app and the desktop app's Tools). The flags, files, events and models in §2–§5 were run against Devin CLI 3000.14.30821 with a Devin Pro account, on the plan's free models, 2026-11-22.
- Date: 2026-11-23
- Extends: ADR 0032 (computer brains), ADR 0041 (accounts per agent), ADR 0053 §3 (permission profiles), ADR 0059 (AI accounts belong to people), ADR 0132 (OpenCode over the Agent Client Protocol, whose client this reuses), ADR 0143 (the Antigravity brain, whose account shape this mirrors), ADR 0137 §4 (the team's right hand on a plan)

## Context

Cognition's Devin CLI (`devin`, docs.devin.ai/cli) is a local coding agent sold with the person's Devin plan (Free, Pro, Max, Teams; Enterprise through SSO). Its quota is the plan's, counted in ACUs from each model's token prices. What it does, read off `devin --help`, its own warnings, `devin doctor` and its answers:

- Install: `curl -fsSL https://cli.devin.ai/install.sh | bash` reads `static.devin.ai/cli/current/manifest.json` (each platform's bundle with its SHA-256), puts the bundle in `$XDG_DATA_HOME/devin/cli/_versions/<version>/` and links `~/.local/bin/devin`, then runs its interactive `devin setup`. Linux, macOS and Windows builds.
- Everything under the XDG folders: the sign-in in `$XDG_DATA_HOME/devin/credentials.toml` (a long-lived token and the API servers, written 644), sessions beside it, settings in `$XDG_CONFIG_HOME/devin/config.json`, its own MCP servers in `mcp_config.json` there. With `HOME` and every XDG folder in a folder of its own it is signed out there and reads nothing of the computer user's.
- Sign-in: `devin auth login --force-manual-token-flow` prints a link on `app.devin.ai/auth/cli/continue` (PKCE) and reads the code that page shows from its terminal only (with a pipe: "Failed to read code - user canceled"); in a terminal the pasted code and Enter sign it in ("Login successful! Credentials stored."). `devin auth status` names the account and its plan; `devin auth logout` signs out. A sign-in in one folder leaves another's as it was.
- Models: `devin models list --format json` lists the account's families (`family_uid`, `family_label`), each with its variants (`model_uid`, `label`, `max_context_tokens`, `cost_tier` "Free" or a price tier, `cost_summary` in USD per million tokens). A variant is a model at one level (`-none`, `-minimal`, `-low`, `-medium`, `-high`, `-xhigh`, `-max`), some with a faster serving (`-fast`, `-priority`, `-lightning`). "Fusion" pairs a main model with a helper (`fusion-<main>-sidekick-<helper>`), hundreds of pairs. Signed out it exits 1: "Not logged in."
- `devin acp [--model <variant>] [--process-model in-process]`: an ACP server on stdio. `initialize` answers `loadSession`, MCP over stdio, HTTP and SSE, and one auth method (the browser's). `session/new` and `session/load` take our MCP servers (stdio with its env, or HTTP); `session/load` replays the history as updates. `configOptions` are `mode` (`accept-edits` "Code", `smart`, `ask`, `plan`, `bypass`) and `model`, which takes only each family's default variant: a variant at another level runs only when `--model` names it as the process starts, and only for a new session (a loaded one keeps the model it began with).
- A turn's updates: `agent_message_chunk`, `agent_thought_chunk`, `tool_call` and `tool_call_update` (`_meta["cognition.ai/toolName"]` `mcp__<server>__<tool>` for an MCP tool, `inferenceToolName` for its own: `exec`, `write`…, output as content), `usage_update`; the prompt's answer carries `stopReason` and `usage` (`inputTokens`, `outputTokens`, `cachedReadTokens`). In Code mode edits in the folder ask nothing; anything else asks with `session/request_permission`, naming its rule (`_meta["cognition.ai/permissionRule"]`: `mcp__agentes__ping`, `Write(/tmp)`, `Exec(…)`) and offering `allow_once`, `allow_always`, `switch_bypass` and `reject_once`.
- Settings it checks: `shell.setup_complete` (else print mode writes the home's `.bashrc`), `auto_update`, `process_model` (`daemon` shares one agent process between `devin` commands), `skip_workspace_trust`, `permission_mode`, `permissions` (`allow`, `deny`, `ask`). Its settings also name other tools whose config it can bring in (Claude Code, Cursor, Codex, Zed, Copilot, `AGENTS.md`), read off its binary: what it reads from the home is not documented.

## Decision

1. **An eighth computer brain** (`BrainKind` and `AccountKind` `devin`, `BRAIN_NAMES` "Devin CLI", `BRAIN_PLAN_NAMES` "Devin", plan choice `devin` with Devin's mark, after Cursor in every picker), the same `brain.turn` as Codex's (`DevinBrain`, `DEVIN_CLI`). Runner protocol 89 (`DEVIN_PROTOCOL`): `brain.turn` `kind: "devin"`, `account` `kind: "devin"`, `hello.executors.devin` (its version line, and the families its accounts listed), `access.tools.devin` (absent: follows Codex's). Missing CLI: `devin_missing`; a failed turn `devin_failed`. No live steering. Usage is the person's plan (tokens recorded, cost zero, as every plan's). Not on Windows yet (`brainRunsOn`, §10).
2. **One `devin acp` per turn** (`brain-devin.ts`, over `acp.ts`), always `--process-model in-process` and, with a model chosen, `--model <variant>`. The variant is `devinVariant` over the family's variants the account listed: the agent's effort, else the nearest level below it, else the nearest above; its faster serving where Velocidade is Rápida and one exists (`speedFits` is true for Devin; where none exists the standard one runs). Our session → Devin's in `devin-sessions.json`, per account and folder, with the variant it ran: the same variant loads it (its replay skipped), another one, or a session Devin no longer has, starts a new one with the engine's context leading the first prompt. Our MCP server goes with each session as OpenCode's does (`opencodeBridge`).
3. **Always an account.** Its folder is the CLI's whole `HOME`, with every XDG folder under it (`accountEnv`), so its sign-in, settings and sessions are its own; every `DEVIN_` and `WINDSURF_` variable of the runner's env or the agent's secrets stays out (and those names are reserved secret names), and so does the display (`DISPLAY`, `WAYLAND_DISPLAY`): with one to reach, its sign-in never prints its link. Before every sign-in, look and turn (`prepareDevinHome`): what a turn could plant for a later one is removed (other tools' config folders and rules files, the CLI's own MCP servers, rules, skills, hooks and plugins), and the settings are ours: shell setup done, no updates of its own, `in-process`, folders trusted, Code mode, no permission rules of its own; the organization the CLI saved at its sign-in is kept; the sign-in file is made 600. Nothing is imported (`read_config_from` all false, `DEVIN_NO_IMPORTS`): no other tool's rules, skills, hooks or MCP servers from the home or the turn's folder, and none of the account's Devin Cloud plugins or MCP servers. Before every turn the agent's own folder loses the `.devin/` files that would run or allow commands (`hooks.v1.json`, `config.json`, `config.local.json`, `mcp_config.json`, `mcp_config.local.json`; `clearDevinProject`), as Cursor's `hooks.json` goes.
4. **Accounts** (ADR 0041, 0059): `devin auth login --force-manual-token-flow` in a terminal of its own (`spawnInTerminal`), its `app.devin.ai` link opened in the person's browser and the code Devin's page shows pasted back, sealed to the computer's key like Claude's and Gemini's. Its look is `devin models list --format json` in its folder: signed in when it lists families, then `devin auth status` for its email and plan, and that list is kept per account (`devin-models.json`, `AccountManager.listedModels`), as Grok's and Gemini's are (ADR 0143 §6, amended 2026-11-20). `devin auth logout` before the folder goes. Where each agent is its own OS user a Devin sign-in is one per agent (`sharesSignIns` false for it), as Cursor's.
5. **Models in the picker** (`devinModels`): one per family the accounts listed (else `DEVIN_MODELS`), with the levels its variants have (`efforts`), whether it has a faster variant (`fast`), its window, and `free` where the plan serves every standard variant at no cost (shown as Grátis, as OpenCode's free models). Fusion is one model per main family, with SWE-2 Medium, the helper served at no cost, as its helper (`DEVIN_FUSION_HELPER`, `fusion-<family>`); the other pairs are left out. The variants stay on the runner: the server never sees them.
6. **Permissions** (ADR 0053 §3): every turn runs in Code mode (`devinMode`), since Ask mode refuses every MCP tool not marked read only, our server's included (seen 2026-11-23), with a settings file of its own (`devin --config <file> acp`, `devinTurnRules`, in `brain/devin-turns/`, removed when the turn ends), so turns of several profiles on one account never share rules: our server's tools allowed (`mcp__agenteschat_agentes__*`); a `plan` turn's `edit`, `exec` and `Write(/**)` denied. A deny refuses the call; it doesn't hide the tool. The runner answers every other request (`devinPermission`): in `work`, commands, and reads and writes in the turn's folder, the agent's own, its allowed folders and the temp folder; in `plan`, reads in those folders; anything else, and any other MCP server, is refused (`reject_once`), never `allow_always` or `switch_bypass`. A turn the CLI ends after a refusal says which permission it asked for.
7. **The team's right hand** (ADR 0137 §4) on a Devin plan: an empty folder of its own, none of the agent's secrets, Code mode with every tool of the CLI's own denied by its rules (`read`, `edit`, `grep`, `glob`, `exec`, `web_search`, `webfetch`, `Fetch(…)`) and its subagents off. The CLI still offers the model its own tools, and a model refused its own web search gave up rather than use ours, so every prompt of such a turn leads with a line naming ours (`DEVIN_CHAT_NOTE`). A refused call of its own goes on quietly; one that runs anyway (`completed`) kills the turn (`devinChatBreach`; listing our server's tools is ours): `tools_not_locked`.
8. **Errors**: the plan's quota or a rate limit in the CLI's words is `plan_limit` with the reset its words give, "Not logged in" or a refused token `not_logged_in`, anything else `devin_failed`. A turn that hears nothing for five minutes with no tool running stops and says so.
9. **Install**: one more pinned CLI (ADR 0228 §6): `CLI_PINS.devin` is the version and each macOS and Linux bundle of Cognition's `manifest.json` with its SHA-256 (`bin/devin` in the bundle), refreshed by `scripts/cli-pins.ts` with the others. A runner fetches it where no copy at that version or newer is there, before a Devin sign-in or turn; in system mode only where no agent's user reaches one (ADR 0228 §7, protocol 88), and the per-agent reach check counts `devin` like every CLI. Self-hosters may still run Cognition's installer (SELF_HOSTING.md); the apps show it where the CLI is missing (`cliInstallCommand`, the desktop's Tools).
10. **Windows**: the pin carries no Windows build, so `brainRunsOn` keeps Devin off Windows computers, and every place that keeps it off says why: the plan pickers' line (`brain.reasons.systemDevin`), the desktop's Tools on Windows (`desktop.tools.devinWindows`, in place of its install line), a refused turn and a refused sign-in.

## Not done

- Devin plans on Windows computers.
- A repository's own `.devin/` (its hooks and MCP servers) in a folder the agent was allowed: the CLI has no switch that skips project settings, and workspace trust is all or nothing (an untrusted folder refuses the session). A deny always wins over a project's allow, so a `plan` turn's rules hold; that repository's hooks still run.
- Telling Lodi's turns the CLI's own tools are gone (`disabled_tools`) instead of denying them: not yet run against an account.
- One Devin sign-in for all of its owner's agents where each agent is its own OS user.
- The plan's usage: the CLI has no usage command, so Configurações › Uso shows the tokens only.
- The CLI's own telemetry: no setting it checks turns it off.
- Fusion with another helper than SWE-2 Medium, and Devin's own model choice inside Adaptive beyond the CLI's.
- A loaded session at another level: Devin keeps a session's model, so a new effort starts a new session (with the context).
- The quota's exact words: none was seen; the limit is read by the usual words.

## Consequences

- A Devin plan thinks for its owner's agents on a Linux or macOS computer whose runner is 89 or newer with the Devin CLI installed, at the effort and speed each agent has, and for Lodi locked to our server's tools.
- Everything Devin-specific is behind runner protocol 89 and `kind: "devin"`: older runners and servers never see it.
- A run at a Devin plan's limit waits for it, as every plan's but Claude's and ChatGPT's does (`NEXT_ACCOUNT_KINDS`).
